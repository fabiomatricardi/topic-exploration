## 3. Curriculum — 4 weekends

Each weekend = **one 3–4 hour block**, structured identically: **Plan → Build → Harden → Ship.**

### Weekend 0 (free preview / prerequisite)
**"Your sandbox in 60 minutes"** — install OpenCode + one local model, run your first session. = the Weekend AI Toolkit path. Delivered free as the lead-magnet preview so buyers arrive ready.

### Weekend 1 — PLAN: "From blinking cursor to buildable blueprint"
- Kill the *“I don't know what to build”* blocker: the **One-Sentence App Spec** (input → process → output → edge cases).
- Size-check rule: if it can't be finished in one sitting, cut it. *"Build me Instagram"* → collapse.
- **Your project:** pick from a catalogue of 12 scope-checked ideas (batch file renamer, expense summarizer, photo organizer, habit tracker, bookmark cleaner…), each pre-approved to fit a weekend and 8 GB RAM.
- **Deliverable:** a written spec you paste into OpenCode as the first message.

### Weekend 2 — BUILD: "Directing the agent (without learning syntax)"
- How to talk to the agent: the **structured prompt** (goal · inputs · steps · output · constraints).
- AGENTS.md as project memory (from your Medium series, Part 3).
- Small one-change loops instead of five-change dumps.
- **Your project:** the agent builds v0 of your app; you verify by *using* it, not by reading code.
- **Deliverable:** a working (ugly) app that does the one thing.

### Weekend 3 — HARDEN: "The Control Room" (your differentiator)
The 6 industrial rules from your *Control Room guide* — compressed into a checklist:
1. **Kill switch** — explicit shutdown endpoint / close button that actually closes (no zombie processes eating RAM).
2. **Own the environment** — `uv` + double-click `.bat` launchers so it runs on any machine, Python not required.
3. **Failure states** — what happens when the folder is empty / the file is wrong / the model is off.
4. **Honest limits** — RAM/CPU budget printed in the app footer.
5. **Reproducibility** — same input → same output, every time.
6. **Cleanup** — no temp files, no background processes after quit.
- **Deliverable:** your app passes the 6-point checklist (a printable scorecard).

### Weekend 4 — SHIP: "It lives on my machine — now what?"
- Local is a feature: package as a standalone `.exe` (PyInstaller, `--noconsole`) OR run as a local web app on `127.0.0.1` (you already teach both).
- Share with family/colleagues: a zip + `start.bat`, no Python needed on their side.
- Backup & versioning: zip the project folder weekly; git *optional*, explained without shame.
- **Your project:** ship v1.0 — something another human can run.
- **Deliverable:** a working app + a one-page "how to run it" sheet with your name on it.

**Capstone:** a 5th bonus session — *"Your 5th weekend: making it yours"* (custom prompts, adding one AI feature with a free API, ideas catalogue part 2).
